# Шпаргалки к экзаменам

Справочник к универскому ивенту в GTA 5 RP. Vite + Vue 3 + TypeScript, архитектура по
Feature-Sliced Design, деплой на GitHub Pages через Actions.

**Главная** — 10 предметов, которые открываются по одному в день с 1 сентября. Даты считаются
в браузере, вручную ничего разблокировать не надо.

Важно: день ивента переключается в **07:00 по Москве**, а не в локальную полночь. Расписание
считает от MSK (UTC+3, без перевода часов) со сдвигом на семь часов, поэтому часовой пояс игрока
на результат не влияет: в три часа ночи по Москве идёт ещё вчерашний день. Логика в
`src/entities/subject/model/schedule.ts` — там же константа `DAY_STARTS_AT_HOUR`.

**Информатика** — решатель для взлома терминала. Вводишь слова с экрана, он подсказывает,
какое жать следующим, и после каждого ответа отсеивает невозможное. Ход выбирается минимаксом:
берётся слово, после которого даже при самом неудачном ответе останется меньше всего вариантов.
На типичном экране из 18 слов это укладывается максимум в 4 попытки из 5.

**Химия** — верстак алхимика на 715 рецептов:

- **Комбинировать** — выбираешь элемент, сетка сужается до тех, с чем он реально смешивается;
  на плитке подписан результат.
- **Как сделать** — пошаговая цепочка с нуля до нужного элемента плюс «где ещё используется».
- **Уровни** — все элементы, разложенные по глубине: базовые, потом то, что собирается за один
  синтез, за два и так далее. Столбики сверху показывают, сколько элементов на каждой ступени.
- **Список** — все рецепты с чекбоксами, прогресс хранится в `localStorage`.

Цифра в углу плитки — сколько синтезов отделяет элемент от четырёх базовых. Поиск фокусируется
клавишей `/`.

Отметить элемент полученным можно откуда угодно: кружком в углу любой плитки, чекбоксом в списке
или на карточке элемента — это один и тот же `useProgressStore`, поэтому отметка сразу видна
на всех вкладках. У базовых элементов и «Времени» метки нет: они есть с самого начала.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173/university/
npm run build      # проверка типов + сборка в dist/
npm run preview    # посмотреть собранное
npm run typecheck  # только типы
```

## Архитектура

Feature-Sliced Design. Слои сверху вниз, импорт разрешён **только вниз**: страница может взять
виджет, виджет — фичу, фича — сущность, все — `shared`. Обратно и вбок (виджет из виджета,
сущность из сущности) — нельзя.

```
src/
├─ app/         инициализация: роутер, глобальные стили, токены темы
├─ pages/       subjects (главная), chemistry (верстак), informatics (терминал)
├─ widgets/     subject-grid, combiner, recipe-path, element-levels, recipe-book,
│               element-detail, terminal-solver
├─ features/    combine-elements, element-search, track-progress, toggle-theme,
│               terminal-session
├─ entities/    element (иконки, плитки), recipe (граф синтезов), subject (расписание),
│               terminal (совпадения, фильтр кандидатов, минимакс)
└─ shared/      ui-кит, утилиты, типы, реактивный localStorage
```

Каждый слайс отдаёт наружу только то, что перечислено в его `index.ts` — внутрь чужого слайса
импортов быть не должно.

Запрет на импорт вбок решён в двух местах:

- `combiner` и `recipe-path` не тянут `element-detail` напрямую, а получают карточку элемента
  слотом от страницы `chemistry`;
- `entities/recipe` рисует ингредиенты компонентом из `entities/element` — через официальную
  витрину cross-import `src/entities/element/@x/recipe.ts`. Это единственный разрешённый
  проход между сущностями, и он объявлен явно.

Состояние — на Pinia, сторы в setup-стиле лежат в сегменте `model` своих фич:

| Стор | Слайс | За что отвечает |
| --- | --- | --- |
| `useCombinerStore` | `features/combine-elements` | слоты A и B, результат пары, список партнёров |
| `useProgressStore` | `features/track-progress` | что получено, счётчик и процент; пишет в `localStorage` |
| `useSearchStore` | `features/element-search` | строка поиска и предикат `matches` для всех списков |
| `useThemeStore` | `features/toggle-theme` | светлая/тёмная тема |
| `useTerminalStore` | `features/terminal-session` | слова с экрана и сделанные попытки взлома |

В компонентах состояние берётся через `storeToRefs` (иначе деструктуризация теряет
реактивность), а экшены — прямо со стора: `combiner.pick(...)`.

Стор химии как таковой не нужен: граф синтезов неизменяем после загрузки и живёт обычным
синглтоном `chemistry` в `entities/recipe`. TanStack Query тоже не подключён — он про серверные
данные и кеш запросов, а здесь всё считается локально из текстового файла.

### Где что менять

**Названия предметов** — `src/entities/subject/model/subjects.ts`. Порядок в массиве `SUBJECTS`
задаёт день открытия: первый элемент открывается 1 сентября, второй 2-го и так далее. Поле
`route` — имя маршрута, который откроется по клику; без него карточка показывает
«гайда пока нет». Дату старта задаёт `EVENT_START` там же (месяцы в JS считаются с нуля,
сентябрь — `8`).

**Подвал: донат и подпись** — `src/shared/config/site.ts`. Впиши в `DONATION_URL` ссылку вида
`https://www.donationalerts.com/r/<ник>` — в подвале появится кнопка «Поддержать». Пустая
строка — кнопки нет. Там же `AUTHOR` и `AUTHOR_URL` для подписи.

Виджеты DonationAlerts (алерты, прогресс-бар цели) на сайт не ставятся: они сделаны под источник
«Браузер» в OBS и рисуются поверх стрима. Страницу доната в iframe тоже вставлять не стоит —
платёжные страницы обычно запрещают встраивание, а на телефоне такой фрейм неудобен.

**Рецепты** — `src/entities/recipe/api/recipes.txt`. Первая значимая строка — базовые элементы
через `|`, дальше по строке на рецепт: `Элемент+Элемент=Результат`. Строки с `#` — комментарии.
Номера проставляются при разборе, так что вставлять можно куда угодно.

**Эмодзи элементов** — `src/entities/element/api/emoji.txt`, пары `Название=эмодзи`.
Для элемента без строки подставляется 🔹.

**Свои картинки вместо эмодзи** — положи PNG в `public/icons` (имя файла = название элемента)
и поставь `USE_IMAGES = true` в `src/entities/element/model/icon.ts`. Подробности —
`public/icons/README.md`.

**Новый предмет с собственным гайдом** — заводишь `src/pages/<предмет>`, добавляешь маршрут
в `src/app/router/index.ts` и прописываешь его имя в поле `route` нужного предмета.

## Деплой на GitHub Pages

Workflow `.github/workflows/deploy.yml` собирает проект на каждый пуш в `main` и публикует `dist`.

Один раз включи это в репозитории: **Settings → Pages → Source: GitHub Actions**
(не «Deploy from a branch» — сборка идёт в Actions).

Сайт живёт на `https://university-5rp.ru`.

### Превью для соцсетей

`public/og.png` — картинка 1200×630, которую показывают Телеграм, ВК, Дискорд и поисковики.
Ссылки на неё в `index.html`: `og:image`, `twitter:image` и `image` в микроразметке.

Исходник картинки — обычная страница `scripts/og.html`; перерисовывается снимком в headless Chrome:

```bash
chrome --headless=new --disable-gpu --hide-scrollbars   --window-size=1200,630 --virtual-time-budget=10000   --screenshot=public/og.png scripts/og.html
```

`--virtual-time-budget` нужен, чтобы успели подгрузиться шрифты с Google Fonts, иначе текст
отрисуется системным. Путь к странице передавай абсолютным `file:///…`.

Соцсети кешируют превью надолго. После замены картинки прогони ссылку через отладчик
(у Телеграма — `@WebpageBot`), иначе будет висеть старая.

### Свой домен

Домен задан в двух местах: `public/CNAME` (попадает в сборку) и Settings → Pages → Custom domain.
DNS у регистратора:

| Тип | Имя | Значение |
| --- | --- | --- |
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| CNAME | `www` | `uptostar.github.io.` |

После того как GitHub проверит записи, включи **Enforce HTTPS** — сертификат выпускается сам.

Три вещи, которые ломают деплой чаще всего:

- **`base` в `vite.config.ts`.** На своём домене сайт лежит в корне, поэтому `'/'`. Если
  вернёшься на `uptostar.github.io/university/`, поставь обратно `'/university/'`, иначе стили
  и скрипты уйдут в 404.
- **Пропавший CNAME.** Файл `public/CNAME` попадает в сборку и не даёт настройке домена
  слететь при переразвёртывании.
- **Приватный репозиторий.** Pages работает с приватными репозиториями только на тарифах
  Pro, Team и Enterprise. На бесплатном репозиторий должен быть публичным.

### Переезд на другой хостинг

Сборка — обычная статика в `dist`, её примет кто угодно. К GitHub привязаны всего четыре вещи:

| Что | Где | Что делать при переезде |
| --- | --- | --- |
| CI-сборка | `.github/workflows/deploy.yml` | удалить или оставить — новый хостинг обычно собирает сам |
| Домен | `public/CNAME` | удалить: файл понимает только GitHub Pages |
| Возврат приложения на любой путь | шаг `cp dist/index.html dist/404.html` | заменить на правило хостинга, см. ниже |
| DNS | A-записи на IP гитхаба | переписать на адреса нового хостинга |

Правило для маршрутов на разных площадках:

- **Netlify, Cloudflare Pages** — уже лежит готовый `public/_redirects`, ничего делать не надо.
- **Vercel** — положи в корень `vercel.json`:
  `{ "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }`
- **nginx** — в блок `location /`: `try_files $uri $uri/ /index.html;`
- **Apache (обычный хостинг с FTP)** — `.htaccess` рядом с файлами:
  `RewriteEngine On` / `RewriteCond %{REQUEST_FILENAME} !-f` / `RewriteRule . /index.html [L]`

Куда обычно едут: Netlify и Cloudflare Pages подхватывают репозиторий и собирают сами, как
Actions — переезд сводится к «подключить репозиторий и сменить DNS». На обычный хостинг с FTP
заливается содержимое `dist` после `npm run build`.

Сам сайт трогать не придётся: `base` уже `'/'`, ссылки относительные, бэкенда нет,
данные лежат в `localStorage` браузера — переносить нечего.

### SEO

Маршруты обычные (`/chem`, `/inf`), а не хешевые: для поисковика `#/chem` — это та же главная,
и отдельной страницей он её не считает. Прямой заход по вложенному пути GitHub Pages отдал бы
404, поэтому в workflow собранный `index.html` копируется в `404.html` — сервер возвращает
приложение на любой путь, а маршрут разбирает уже роутер.

Что настроено:

- `index.html` — title, description, canonical, Open Graph, `theme-color` под обе темы
  и микроразметка JSON-LD (`WebApplication`).
- `public/robots.txt` и `public/sitemap.xml` — со всеми тремя адресами.
- `src/app/router/meta.ts` — при переходе обновляет заголовок вкладки, описание и canonical.
  Переименуешь домен — поправь `SITE_URL` в `src/shared/config/site.ts`, а также ссылки
  в `robots.txt`, `sitemap.xml` и `index.html`.

Чего нет и почему:

- **Превью-картинки (`og:image`).** Нужен PNG 1200×630. Положишь его в `public/og.png` —
  добавь в `index.html` строку
  `<meta property="og:image" content="https://university-5rp.ru/og.png">`. Без файла лучше
  тега не ставить: часть мессенджеров на битую картинку показывает пустое превью.
- **Разного описания для соцсетей на каждой странице.** Телеграм, ВК и Дискорд читают исходный
  HTML и скрипты не выполняют, поэтому в превью любой ссылки попадёт описание главной. Обойти
  это можно только пререндером — для сайта на десять дней оно того не стоит.

После первого деплоя добавь сайт в Яндекс.Вебмастер и Google Search Console и скорми им
`sitemap.xml` — сам по себе он в поиск ничего не ускоряет.

## Расхождения с исходным списком

В гайде несколько разных предметов назывались одинаково — такие рецепты затирали друг друга,
поэтому они переименованы:

| В гайде | Здесь |
| --- | --- |
| Нефть (Подсолнух + Давление) | Растительное масло |
| Нефть (Молоко + Давление) | Сливочное масло |
| Сок (Дерево + Клинок) | Древесный сок |
| Пиво (Пиво + Пшеница) | Светлое пиво |
| Котёл (Керамика + Металл) | Котелок |
| Икра (Икра + Соль) | Чёрная икра |
| Труба (Табак + Инструмент) | Курительная трубка |

Если в игре названия другие — поправь их в `recipes.txt` и `emoji.txt`.
